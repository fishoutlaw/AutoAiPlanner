# AutoAiPlanner

[English](README.md) | 한국어

AutoAiPlanner는 직접 입력과 자연어 AI 기능을 함께 제공하는 브라우저 기반 개인 계획 관리 앱입니다. 일정, 할 일, 프로젝트, 중간 목표를 한곳에서 관리하며 앱 데이터는 기본적으로 현재 브라우저에 저장됩니다.

## 개요

AutoAiPlanner는 계정이나 백엔드 서버 없이 개인 계획을 정리할 수 있는 외부 의존성 없는 정적 SPA입니다. 항목을 직접 입력하거나 설정한 AI 공급자에게 생성·수정을 요청할 수 있으며, AI 결과는 저장 전에 미리 확인할 수 있습니다.

앱에서 관리하는 항목은 다음과 같습니다.

- 시작·종료 시간을 선택적으로 지정할 수 있는 일정
- 기한 날짜와 시간을 선택적으로 지정할 수 있는 할 일
- 기간과 연결 항목을 관리하는 프로젝트
- 프로젝트 기간 안에 배치하는 중간 목표

앱 데이터는 브라우저에 로컬로 저장됩니다. 간편하게 실행할 수 있는 대신 계정 기반 클라우드 백업이나 동기화는 제공하지 않습니다.

## 라이브 데모

아직 배포되지 않았습니다. [시작하기](#시작하기)를 따라 로컬에서 실행하세요.

## 주요 기능

- 일정 요약, 할 일 빠른 추가, 시작 문구 수정을 지원하는 대시보드
- 종일 또는 시작·종료 시간을 선택할 수 있는 일정 직접 추가·수정
- 할 일 빠른 추가, 완료, 수정, 삭제, 일정 전환
- 기간, 중간 목표, 연결 일정, 연결 할 일을 포함하는 프로젝트
- 한 달 보기와 연속으로 스크롤할 수 있는 여러 달 달력
- 일정, 할 일, 프로젝트, 중간 목표를 구분하는 달력 표시
- 일정 표시점과 프로젝트 기간 선의 사용자 지정 색상
- 검토 단계를 포함한 AI 생성, 프로젝트 구체화, 자연어 수정
- 엔드포인트·모델 ID 수정, 연결 테스트, API 도움말을 포함한 공급자 설정
- 라이트·다크·시스템 테마, 모바일 반응형 화면, 접근 가능한 레이블·포커스 처리, 모션 감소
- 로컬 저장, JSON 백업·가져오기, v1·v2 이전, 열린 탭 사이 동기화
- 삭제 확인 설정과 초기 예시 데이터 복원

## 기술 스택

- HTML5
- CSS3
- Vanilla JavaScript
- Web Storage APIs: `localStorage`, `sessionStorage`
- Fetch API
- JSON Schema 기반 AI 응답 검증

패키지 설치, 빌드 과정, 프레임워크, TypeScript 런타임, 서버 데이터베이스, 외부 UI 의존성을 사용하지 않습니다. 로컬 정적 서버는 파일 실행을 돕는 수단일 뿐 앱의 런타임 의존성이 아닙니다.

## 시작하기

별도 의존성을 설치하거나 빌드할 필요가 없습니다.

1. 프로젝트를 다운로드하거나 복사합니다.
2. 프로젝트 폴더에서 터미널을 엽니다.
3. 앱 폴더로 이동한 뒤 정적 HTTP 서버를 실행합니다.

```bash
cd auto-ai-planner
python -m http.server 8000
```

4. 브라우저에서 `http://localhost:8000`을 엽니다.

Python을 사용할 수 없다면 다른 정적 파일 서버를 이용하세요. 로컬 기능만 사용할 때는 `index.html`을 직접 열 수도 있지만, 외부 AI 공급자가 브라우저 및 CORS 정책을 적용할 수 있으므로 HTTP 서버 실행을 권장합니다.

## AI 공급자 설정

AutoAiPlanner는 다음 공급자 모드를 지원합니다.

- **체험 모드:** API 키와 외부 AI 요청이 없는 로컬 모의 흐름
- **Google Gemini:** Gemini Interactions API 어댑터
- **GroqCloud:** OpenAI 호환 Chat Completions 어댑터
- **OpenRouter:** 무료 모델 목록, 무료 모델 자동 선택, 모델 ID 직접 입력
- **사용자 지정 OpenAI 호환 API:** 사용자가 입력하는 Chat Completions 엔드포인트와 모델 ID

공급자 설정 방법은 다음과 같습니다.

1. **설정**을 엽니다.
2. AI 서비스를 선택합니다.
3. 엔드포인트와 모델을 확인하거나 수정합니다.
4. 필요한 경우 API 키를 입력합니다.
5. 현재 세션에서만 키를 유지할지, 이 기기에 저장할지 선택합니다.
6. 연결 테스트를 실행합니다.
7. 설정을 저장합니다.

공급자 엔드포인트와 모델 ID는 변경될 수 있습니다. 신뢰할 수 있는 공급자가 제공한 값만 사용하세요. 체험 모드가 아닐 때는 브라우저가 API 키와 요청에 필요한 내용을 선택한 공급자에게 직접 전송하며, AutoAiPlanner 자체 백엔드를 거치지 않습니다.

## 데이터 저장

- 기본 앱 데이터는 `localStorage`의 `autoAiPlanner.appData.v3` 키를 사용합니다.
- v1 또는 v2 키에 저장된 데이터는 정규화한 뒤 v3로 자동 이전합니다.
- 일정, 할 일, 프로젝트, 중간 목표, 프로필, 환경설정, 최근 프롬프트, API 프로필이 현재 브라우저에 저장됩니다.
- 세션 전용 API 키는 `sessionStorage`에 저장되며 현재 탭 또는 브라우저 세션 범위에서 사용됩니다.
- 기기에 저장한 API 키는 `localStorage`를 사용하므로 브라우저를 닫은 뒤에도 남을 수 있습니다.
- JSON 내보내기·가져오기는 앱 데이터와 설정을 포함하지만 내보낸 백업에는 API 키가 포함되지 않습니다.
- v3 앱 데이터 변경은 브라우저의 `storage` 이벤트를 통해 열린 탭 사이에 반영됩니다.
- 별도 백업 없이 브라우저 사이트 데이터를 삭제하면 로컬 데이터를 복구하지 못할 수 있습니다.
- 여러 기기 사이 자동 동기화는 제공하지 않습니다.

## 기술적 결정

- **외부 의존성 없는 정적 구조:** 실행 파일 세 개만으로 쉽게 옮기고 코드를 확인할 수 있지만, 프레임워크 없이 UI와 상태 동작을 직접 관리해야 합니다.
- **중앙 메모리 상태와 렌더 함수:** 하나의 상태 객체를 사용해 화면 동작을 일관되게 유지하지만, 큰 렌더 함수의 흐름을 주의해서 관리해야 합니다.
- **`data-action` 기반 이벤트 위임:** 동적으로 생성되는 컨트롤이 문서 수준 이벤트 처리기를 공유해 중복 리스너를 줄이는 대신 액션 이름이 내부 동작 규약이 됩니다.
- **데이터 수용 전 정규화:** 저장·가져오기·AI 생성 데이터가 검증 없이 상태에 들어가지 않게 하며, 잘못된 값은 안전한 기본값으로 바뀔 수 있습니다.
- **이전 버전 호환:** v1·v2 데이터를 v3로 이전하고 기존 여러 날 일정을 프로젝트로 변환해 데이터를 보존하는 대신 이전 로직이 추가됩니다.
- **공통 응답 봉투와 공급자 어댑터:** Gemini와 OpenAI 호환 서비스는 서로 다른 요청 형식을 사용하지만 앱 내부에서는 공통 엔터티 응답 형식을 사용합니다.
- **JSON Schema 기반 구조화 출력:** 지원 모델에는 작업별 Schema를 전달하고, 나머지 모델에는 기본 JSON 모드를 사용한 뒤 동일한 앱 내부 파싱과 검증을 적용합니다.
- **브라우저 전용 저장:** 필수 백엔드가 없지만 브라우저 저장 공간, 백업, 프론트엔드 API 키 노출을 사용자가 직접 관리해야 합니다.
- **공통 엔터티의 상황별 렌더링:** 일정·할 일·프로젝트 렌더러를 대시보드, 상세 화면, 달력, 모달에서 재사용하면서 상황에 맞는 컨트롤을 제공합니다.

## 보안

- API 키는 내보낸 백업 파일에 포함되지 않습니다.
- 세션 전용 키는 현재 탭 또는 브라우저 세션 범위의 `sessionStorage`에 저장됩니다.
- 기기에 저장한 키는 `localStorage`에 암호화되지 않은 상태로 남을 수 있습니다. 공용·공유 기기에서는 기기 저장을 켜지 마세요.
- 이 앱은 정적 프론트엔드이므로 API 키가 브라우저에서 사용되며 백엔드 비밀 저장소의 보호를 받지 않습니다.
- 사용자 입력을 생성된 HTML에 넣을 때 `escapeHTML()`로 이스케이프합니다.
- 저장 데이터, 가져온 데이터, AI 생성 데이터는 사용 전에 정규화하고 검증합니다.
- 사용자 지정 공급자 엔드포인트와 모델 ID는 신뢰할 수 있는 대상일 때만 입력해야 합니다.
- API 키, `.env` 파일, 개인 `AutoAiPlanner-backup-*.json` 파일을 Git에 커밋하지 마세요.

브라우저 저장 공간은 암호화된 보안 저장소가 아닙니다. 민감한 일정이나 프로젝트 내용을 보내기 전에 선택한 공급자의 데이터 처리 정책을 확인하세요.

├─ app.js

- `README.md`: 기본 영문 문서
- `README.ko.md`: 한국어 문서

## 제한사항

- 데이터는 브라우저에만 저장되며 계정이나 클라우드 동기화가 없습니다.
- 여러 사용자 간 협업을 지원하지 않습니다.
- 공급자 가용성, 브라우저 CORS 규칙, 사용량 한도, 가격, 모델 동작은 앱에서 통제할 수 없습니다.
- API 키가 브라우저에서 직접 사용됩니다.
- Schema 안내와 앱 내부 검증을 사용해도 AI 결과에는 사용자 검토가 필요합니다.
- 브라우저 저장 용량과 사용자의 사이트 데이터 삭제로 인해 데이터가 손실될 수 있습니다.
- 탭 사이 반영은 같은 브라우저 저장 영역에서만 동작하며 여러 기기에는 적용되지 않습니다.
- 자동화된 테스트 스위트와 CI 파이프라인이 없습니다.
- 확인된 호스팅 라이브 데모가 없습니다.
